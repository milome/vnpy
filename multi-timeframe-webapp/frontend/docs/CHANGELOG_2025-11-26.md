## 🆕 新功能

### 1. K线信息实时显示

**功能描述**：当光标移动到某根K线时，左上角信息面板实时显示该K线的详细数据。

#### 显示内容

| 项目 | 颜色 | 说明 |
|------|------|------|
| 时间 | 灰色 | 完整日期时间 + 星期几 |
| 开盘价 | 白色 | |
| 最高价 | 红色 | |
| 收盘价 | 白色 | |
| 最低价 | 绿色 | |
| 涨跌 | 红/绿 | 点数变化 + 百分比 |
| 成交量 | 蓝色 | 带千分位分隔符 |

#### 界面示例

```
┌─────────────────────────────┐
│  2025/11/26 周二 14:30      │  ← 时间日期
├─────────────────────────────┤
│  开: 21050    高: 21080     │  ← OHLC数据
│  收: 21065    低: 21040     │
├─────────────────────────────┤
│  涨跌: +15 (+0.07%)         │  ← 红涨绿跌
│  成交量: 1,234              │  ← 蓝色显示
├─────────────────────────────┤
│  图层                       │
│  ■ 1分钟  ■ 4小时           │
└─────────────────────────────┘
```

#### 交互行为

- **移动光标到K线** → 显示该K线的完整信息
- **光标移出图表** → 显示 "移动光标查看K线数据" 提示

#### 实现细节

- 通过 `crosshairMove` 事件获取当前光标位置的K线数据
- OHLC数据从series获取，成交量从原始数据中匹配时间戳获取
- 涨跌计算基于当根K线的开盘价和收盘价

### 2. 双止损保护功能

**场景描述**：当挂单成交后，交易员希望迅速将止损线移动到成本线附近以减少风险。但在拖动过程中可能会犹豫，此时如果价格突然反向波动，原有的止损保护就会失效。

**解决方案**：在拖动止损线时，自动创建一条"影子止损线"作为备用保护。

#### 功能特点

| 特性 | 说明 |
|------|------|
| 自动激活 | 开始拖动止损线时自动创建影子线 |
| 滞后跟随 | 影子线跟随主止损线移动，但速度更慢（默认30%） |
| 视觉区分 | 影子线使用半透明橙色点线样式 |
| 状态显示 | 右上角提示框显示原止损、保护线、新止损三个价格 |

#### 实现文件

- `frontend/src/hooks/useDualStopLoss.ts` - 双止损保护Hook
- `frontend/src/tests/useDualStopLoss.test.ts` - 单元测试

#### 使用流程

```
1. 挂单成交后，图表显示止损线（橙色虚线）
2. 开始拖动止损线
   → 自动创建影子止损线（半透明，显示"保护止损 @ 价格"）
   → 右上角显示 🛡️ 双止损保护提示
3. 拖动过程中
   → 主止损线跟随鼠标
   → 影子线滞后跟随（速度为主线的30%）
4. 松开鼠标
   → 确认新止损位置
   → 删除影子线
5. 按ESC或移出图表
   → 取消操作
   → 恢复原止损位置
```

### 3. 从成本线拖拽创建止损/止盈线

**场景描述**：成交后快速设置止损/止盈，无需打开弹窗。

#### 功能特点

| 订单方向 | 拖拽方向 | 创建类型 | 颜色 |
|----------|----------|----------|------|
| 多单（买入）| 向下拖 ↓ | 止损线 | 橙色 |
| 多单（买入）| 向上拖 ↑ | 止盈线 | 蓝色 |
| 空单（卖出）| 向上拖 ↑ | 止损线 | 橙色 |
| 空单（卖出）| 向下拖 ↓ | 止盈线 | 蓝色 |

#### 实现文件

- `frontend/src/hooks/useEntryLineDrag.ts` - 入场线拖拽Hook

#### 使用流程

```
1. 挂单成交后，图表显示入场线（成本线，红色/绿色实线）
2. 从成本线开始拖拽（需移动至少15像素）
   → 根据拖拽方向自动判断线类型
   → 显示预览线（半透明虚线）
   → 右上角提示框显示成本价、目标价、点差
3. 拖拽过程中
   → 线类型可能随方向变化
   → 实时更新预览线位置
4. 松开鼠标
   → 创建正式的止损/止盈线
   → 更新订单数据
```

## 🐛 Bug修复

### 1. 双击成本线时错误创建止损线

**问题描述**：双击成本线时会先触发mousedown（开始创建止损线），然后mouseup（确认创建），导致错误创建了止损线。

**解决方案**：添加最小拖拽距离检测（15像素）

| 动作 | 移动距离 | 结果 |
|------|----------|------|
| 点击/双击 | < 15px | 不创建止损/止盈线 |
| 真正的拖拽 | ≥ 15px | 创建止损/止盈线 |

**修改文件**：`frontend/src/hooks/useEntryLineDrag.ts`

---

### 2. 双击检测优先级问题

**问题描述**：当成本线、止损线、止盈线距离较近时，双击可能被识别为错误的线。

**解决方案**：优化 `findNearestOrderLine` 的优先级策略

| 情况 | 返回的线 |
|------|----------|
| 只有一条线在范围内 | 返回该线 |
| 最近的线距离 < 5像素 | 返回最近的线（明确选择）|
| 有入场线在范围内 | **优先返回入场线** |
| 有挂单线在范围内 | 优先返回挂单线 |
| 其他情况 | 返回距离最近的线 |

**修改文件**：`frontend/src/hooks/usePriceLineDrag.ts`

---

### 3. 下单弹窗在小屏幕上确认按钮不可见

**问题描述**：设置止盈后，弹窗内容过长，确认按钮被遮挡。

**解决方案**：
- 弹窗最大高度限制 `max-height: 90vh`
- 内容区域可滚动
- 头部和底部固定
- 添加自定义滚动条样式

**修改文件**：`frontend/src/components/OrderDialog.css`

---

### 4. 数据加载状态混乱

**问题描述**：
1. 选择日期后立即显示加载状态（用户还没点击加载）
2. 加载弹窗进度与实际加载不同步

**解决方案**：
1. 区分首次加载和用户触发的加载
2. 简化弹窗为确认窗口（不显示虚假进度）
3. 图表显示真实的加载阶段

**修改文件**：
- `frontend/src/App.tsx`
- `frontend/src/components/DataLoadingDialog.tsx`
- `frontend/src/components/TradingViewChart.tsx`
