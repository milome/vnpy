# DataManager改进总结

## 概述

本次改进主要涉及DataManager模块的数据更新功能优化、自动更新功能实现以及完整的测试用例添加。所有改进已完成并通过测试。

## 一、统一进度对话框功能

### 1.1 问题背景

**之前的实现：**
- 点击"更新数据"后，每次调用`output()`回调函数都会弹出新的`QMessageBox`弹窗
- 多个弹窗同时出现，用户体验差
- 无法统一查看所有更新进度信息
- 下载进度对话框设计简单，信息展示不完整

**现在的实现：**
- 创建了统一的`UpdateProgressDialog`类，替代原来的`QProgressDialog`
- 创建了统一的`DownloadProgressDialog`类，与更新进度对话框采用相同设计
- 所有更新/下载信息都显示在同一个对话框中
- 提供详细的消息列表，带时间戳记录
- 统一的UI设计和用户体验

### 1.2 核心改进

#### `UpdateProgressDialog`类（更新进度对话框）

**功能特性：**
- 进度条显示（百分比）
- 当前任务标签（显示正在处理的合约）
- 消息列表（显示所有更新信息，带时间戳）
- 统计信息（完成数量和总数据量）
- 关闭按钮（更新完成后启用）

**关键方法：**
- `set_total_tasks(total)`: 设置总任务数
- `update_progress(current, total, task_name)`: 更新进度
- `append_message(msg)`: 追加消息到消息列表
- `set_completed(total_bars, completed, total)`: 设置为完成状态

#### `DownloadProgressDialog`类（下载进度对话框）

**功能特性：**
- 与`UpdateProgressDialog`采用相同的设计风格
- 进度条显示（百分比或数据量）
- 当前任务标签（显示当前下载阶段）
- 消息列表（显示所有下载信息，带时间戳）
- 统计信息（已下载数据量和进度百分比）
- 关闭按钮（下载完成后启用）
- 错误状态显示（下载失败时显示错误信息）

**关键方法：**
- `append_message(msg)`: 追加消息到消息列表
- `update_progress(stage, current, maximum)`: 更新进度
- `set_completed(total)`: 设置为完成状态
- `set_error(error_msg)`: 设置为错误状态

#### 修改的代码

**`update_data()`方法改进：**
```python
# 创建统一的进度对话框
dialog: UpdateProgressDialog = UpdateProgressDialog(self)
dialog.set_total_tasks(total)
dialog.show()

# 创建自定义的output回调，将消息追加到进度对话框
def output_callback(msg: str) -> None:
    """将消息追加到进度对话框，而不是弹出新弹窗"""
    dialog.append_message(msg)
    QtWidgets.QApplication.processEvents()
```

**`output()`方法改进：**
```python
def output(self, msg: str) -> None:
    """输出下载过程中的日志（保留兼容性，但不再弹出弹窗）"""
    # 不再弹出弹窗，只打印日志
    print(f"[数据下载] {msg}")
```

## 二、异步定时自动更新功能

### 2.1 功能特性

DataManager现在支持定时自动更新数据功能：

- **自动更新开关**：通过复选框启用/禁用
- **更新间隔设置**：5-1440分钟可配置（默认60分钟）
- **下次更新时间显示**：实时显示下次自动更新的时间
- **静默更新**：后台执行，不显示进度对话框
- **防重复更新**：使用`is_updating`标志防止重复执行

### 2.2 UI改进

**新增控件：**
- 自动更新分组框（`QGroupBox`）
- 启用复选框（带状态指示）
- 间隔设置数字输入框（5-1440分钟）
- 下次更新时间标签（动态更新）

**UI布局：**
```
[刷新] [导入数据] [更新数据] [下载数据] | [自动更新] 间隔: [60] 分钟 [下次更新: 15:30]
```

### 2.3 核心实现

#### 自动更新相关方法

**`on_auto_update_changed(state)`**
- 处理复选框状态变化
- 启用/禁用时自动启动/停止定时器
- 更新UI状态（文本、样式）

**`on_auto_update_interval_changed(value)`**
- 处理间隔设置变化
- 如果已启用，重新启动定时器

**`start_auto_update()`**
- 创建并启动QTimer定时器
- 设置定时器间隔（分钟转毫秒）
- 更新下次更新时间显示

**`stop_auto_update()`**
- 停止定时器
- 清空下次更新时间显示

**`auto_update_data()`**
- 触发自动更新（异步执行）
- 检查`is_updating`标志，防止重复更新

**`_execute_auto_update()`**
- 执行静默更新（后台执行）
- 不显示进度对话框，只输出日志
- 更新完成后重置`is_updating`标志

#### 窗口关闭处理

```python
def closeEvent(self, event) -> None:
    """窗口关闭时停止自动更新"""
    self.stop_auto_update()
    event.accept()
```

### 2.4 自动更新流程

```
1. 用户启用自动更新
   ↓
2. 启动QTimer定时器
   ↓
3. 定时器触发 → auto_update_data()
   ↓
4. 检查is_updating标志
   ├─ 如果正在更新 → 跳过本次更新
   └─ 如果未更新 → 设置is_updating=True
      ↓
5. 异步执行_execute_auto_update()
   ↓
6. 静默更新所有合约数据
   ├─ 下载数据
   ├─ 合成5分钟数据
   ├─ 合成1小时数据
   └─ 合成4小时数据
   ↓
7. 更新完成，重置is_updating=False
   ↓
8. 更新下次更新时间显示
```

### 2.5 配置说明

- **默认间隔**：60分钟
- **最小间隔**：5分钟
- **最大间隔**：1440分钟（24小时）
- **更新方式**：静默更新（后台执行，不显示对话框）

### 2.6 日志规范化

**改进内容：**
- 所有日志使用`engine.main_engine.write_log()`输出到VeighNa日志系统
- 统一日志前缀：`[自动更新]`、`[数据更新]`
- 规范化日志格式，便于查看和调试
- 间隔改变时只输出一条日志，避免冗余

**日志格式示例：**
```

[自动更新] 开始执行自动更新任务...

[自动更新] 下次自动更新将在 60 分钟后执行
```

**数据更新日志格式：**

## 七、使用说明

### 7.1 统一进度对话框

**更新数据：**
1. 点击"更新数据"按钮
2. 弹出统一的更新进度对话框
3. 查看实时更新进度和详细信息
4. 更新完成后点击"关闭"按钮

**下载数据：**
1. 点击"下载数据"按钮
2. 填写合约信息（代码、交易所、周期、开始日期）
3. 点击"下载"按钮
4. 下载数据窗口自动关闭，显示下载进度对话框
5. 查看实时下载进度和详细信息
6. 下载完成后点击"关闭"按钮

**对话框内容：**
- 当前任务：显示正在处理的合约/下载阶段
- 进度条：显示完成百分比或数据量
- 信息列表：显示所有更新/下载日志（带时间戳）
- 统计信息：显示完成数量和总数据量

### 7.2 自动更新功能

**启用自动更新：**
1. 勾选"自动更新"复选框
2. 设置更新间隔（5-1440分钟）
3. 系统将按设定间隔自动更新数据

**自动更新特点：**
- 后台静默执行，不显示进度对话框
- 自动更新所有合约的数据
- 自动合成5分钟、1小时、4小时数据

**禁用自动更新：**
- 取消勾选"自动更新"复选框

## 八、技术细节

### 8.1 统一进度对话框实现

**关键设计：**
- 使用`QTextEdit`显示消息列表，支持滚动查看
- 自动滚动到底部，显示最新消息

- 进度条实时更新，显示完成百分比

**消息格式：**
```
[HH:MM:SS] 消息内容
```

### 8.2 下载进度对话框实现

**关键设计：**
- 与更新进度对话框采用相同的布局和样式
- 使用`QTextEdit`显示消息列表，支持滚动查看
- 自动滚动到底部，显示最新消息
- 使用时间戳标记每条消息
- 支持确定和不确定两种进度模式

**消息格式：**
```
[HH:MM:SS] 消息内容
```

**进度显示：**
- 确定模式：显示"已下载: X / Y 条 (Z%)"
- 不确定模式：显示"已获取 X 条数据"

### 8.3 自动更新实现

**定时器机制：**
- 使用`QTimer`实现定时触发
- 间隔时间转换为毫秒：`interval * 60 * 1000`
- 定时器在窗口关闭时自动停止

**异步执行：**
- 使用`QTimer.singleShot(0, callback)`实现异步执行
- 避免阻塞UI线程
- 使用`is_updating`标志防止重复执行

**静默更新：**
- 不显示进度对话框
- 使用`silent_output`回调，只输出日志
- 更新完成后更新下次更新时间显示

### 8.4 日志规范化实现

**日志输出方式：**
- 使用`engine.main_engine.write_log()`替代`print()`
- 所有日志统一输出到VeighNa日志系统
- 带时间戳，便于追踪

**日志前缀规范：**
- `[数据更新]`：数据更新相关日志
- `[自动更新]`：自动更新相关日志
- `[数据下载]`：数据下载相关日志（保留兼容性）

**日志内容规范：**
- 开始/结束：明确标识任务开始和结束
- 进度信息：显示当前进度和统计信息
- 错误信息：包含错误描述和详细堆栈

## 九、注意事项

### 9.1 自动更新

- **资源消耗**：自动更新会消耗系统资源，建议根据实际需求设置合理的更新间隔
- **网络依赖**：自动更新需要网络连接，确保数据源可用
- **数据完整性**：自动更新是静默执行，建议定期检查数据完整性

### 9.2 进度对话框

- **长时间更新/下载**：如果任务很多，对话框可能需要较长时间
- **取消功能**：当前版本不支持取消更新/下载，需要等待完成
- **日志查看**：所有更新/下载日志都保存在对话框中，可以滚动查看
- **窗口关闭**：下载数据窗口在点击下载按钮后会自动关闭

### 9.3 日志

- **日志位置**：所有日志输出到VeighNa日志系统，可在主界面日志栏查看
- **日志格式**：统一使用`[前缀]`格式，便于过滤和查找
- **日志级别**：当前所有日志均为信息级别

### 9.4 测试

- **运行环境**：测试需要pytest和相关依赖
- **Qt环境**：UI测试需要Qt环境支持
- **Mock数据**：测试使用Mock数据，不会影响实际数据库
