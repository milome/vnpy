# 富途 OpenD 延迟优化项目总结

**项目时间**: 2025-01-27  
**项目目标**: 优化富途 OpenD API 延迟，提升实时交易系统性能  
**优先级**: P0（关键性能优化）

---

## 一、项目背景

### 1.1 性能目标

根据实时交易系统的性能要求，制定了以下目标：

| 指标 | 目标值 | 说明 |
|------|--------|------|
| Tick更新延迟 | <100ms | 实时行情数据更新 |
| 图表刷新延迟 | <50ms | K线图表实时刷新 |
| 价格突破触发延迟 | <200ms | 交易信号触发 |
| K线历史加载延迟 | <50ms | 历史数据查询 |

### 1.2 现状问题

通过性能分析发现以下关键问题：

1. **基础报价延迟**: 53.77ms（超出图表刷新目标3.77ms）
2. **UserInfo延迟**: 734.33ms（极高，但调用频率低）
3. **StaticInfo延迟**: 463.19ms（高延迟，调用频率中等）
4. **RequestHistoryKL延迟**: 124.41ms（超出目标74.41ms）

## 三、优化方案概述

### 3.1 缓存机制优化

#### UserInfo 缓存
- **目标**: 734.33ms → <1ms（缓存命中时）
- **策略**: 
  - TTL: 3600秒（1小时）
  - 启动时预加载
  - 连接断开时清空
- **预期效果**: 性能提升 >700x
- **状态**: 📋 方案已设计，待实施

#### StaticInfo 缓存
- **目标**: 463.19ms → <1ms（缓存命中时）
- **策略**:
  - TTL: 86400秒（24小时）
  - 按市场+产品类型缓存
  - 支持选择性刷新
- **预期效果**: 
  - 单次查询: >400x 提升
  - 787次查询总耗时: 364.5秒 → <1秒
- **状态**: 📋 方案已设计，待实施

### 3.2 连接生命周期优化

#### 登录阶段打点
- **目标**: 定位 UserInfo 734ms 延迟发生在哪个阶段
- **实施内容**:
  - `connect_trade()` 打点
  - `connect_quote()` 打点
  - `query_data()` 打点
- **状态**: 📋 方案已设计，待实施

#### 长连接检查
- **目标**: 避免不必要的重复 connect/close
- **实施内容**:
  - 连接状态管理（`self.connected`）
  - 重复连接检测
  - 连接存活时长统计
- **状态**: 📋 方案已设计，待实施

### 3.3 本地处理优化

#### RequestHistoryKL 优化
- **目标**: 124.41ms → <50ms
- **优化方向**:
  - 优化K线数据转换逻辑（减少15-20ms）
  - 分页加载机制
  - 预加载常用周期数据
- **状态**: 📋 待设计详细方案

#### 基础报价推送优化
- **目标**: 53.77ms → <50ms
- **优化方向**:
  - 优化Tick数据解析（减少10-15ms）
  - 批量处理多个tick更新
  - 减少UI刷新频率
- **状态**: 📋 待设计详细方案

## 七、技术要点

### 7.1 缓存设计原则

1. **线程安全**: 使用 `RLock` 保护所有缓存操作
2. **TTL策略**: 根据数据变化频率设置合理的TTL
3. **缓存失效**: 连接断开时自动清空，避免脏数据
4. **性能优先**: 缓存命中时延迟 <1ms

### 7.2 连接生命周期管理

1. **状态跟踪**: 使用 `self.connected` 标记连接状态
2. **重复检测**: 防止不必要的重复连接
3. **存活统计**: 记录连接存活时长，便于分析
4. **最佳实践**: 应用生命周期内只 connect 一次

### 7.3 性能监控

1. **打点日志**: 使用统一前缀 `[LoginProfile]` 和 `[ConnLifecycle]`
2. **延迟统计**: 记录各阶段耗时，便于定位瓶颈
3. **异常检测**: 识别异常延迟和频繁重连

## 八、风险与注意事项

### 8.1 实施风险

1. **调用位置不确定**: UserInfo 可能是 SDK 内部自动调用，需要先确认
2. **接口可能不存在**: 如果找不到直接接口，可能需要使用替代方案
3. **数据一致性**: 缓存数据可能过期，需要合理的TTL策略

### 8.2 注意事项

1. **内存占用**: 缓存会占用一定内存，但通常 <50MB，可接受
2. **日志量**: 打点会增加日志量，建议在生产环境适度使用
3. **向后兼容**: 所有修改都是新增功能，不影响现有功能
