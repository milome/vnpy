# 问题诊断：多周期模式数据加载失败

## 问题描述

- **症状**: 切换到多周期模式后显示空白
- **日志**: "未找到1分钟K线数据"
- **确认**: 单周期模式可以正常加载数据，数据库有数据

## 根本原因

**关键问题**: `database.load_bar_data()` 的 `symbol` 参数格式不对

### 数据库查询参数说明

`database.load_bar_data()` 函数的参数：

```python
def load_bar_data(
    symbol: str,        # ← 注意：这里是 symbol，不是 vt_symbol！
    exchange: Exchange,
    interval: Interval,
    start: datetime,
    end: datetime
) -> List[BarData]:
    pass
```

**重要区别**:
- **symbol**: 不带交易所后缀，如 `"MHImain"`
- **vt_symbol**: 带交易所后缀，如 `"MHImain.HKFE"`

### 问题代码

在 `vnpy/chart/multi_timeframe_widget.py` 中：

```python
# ❌ 错误：传入的是 vt_symbol（如 "MHImain.HKFE"）
one_minute_bars = database.load_bar_data(
    self._vt_symbol,    # ← 这里应该是 symbol，不是 vt_symbol
    self._exchange,
    interval=Interval.MINUTE,
    start=self._start,
    end=self._end,
)
```

数据库表中存储的是：
- symbol: `"MHImain"`
- exchange: `Exchange.HKFE`

但查询时传入的是：
- symbol: `"MHImain.HKFE"` ← 多了 `.HKFE` 后缀，查不到数据！

### 另一个问题

在 `vnpy/trader/ui/widget.py` 的 `sync_data_to_multi_timeframe()` 中：

```python
symbol, exchange = extract_vt_symbol(self.current_vt_symbol)
# symbol = "MHImain", exchange = Exchange.HKFE

# ❌ 错误：传入 vt_symbol 而不是 symbol
self.multi_timeframe_widget.switch_symbol(
    vt_symbol=self.current_vt_symbol,  # ← "MHImain.HKFE"
    exchange=exchange,
    start=start_datetime,
    end=end_datetime
)
```

## 解决方案

### 修复1: 修改 ChartWindow 的调用

在 `vnpy/trader/ui/widget.py` 中：

```python
# ✅ 正确：传入 symbol（不带交易所后缀）
self.multi_timeframe_widget.switch_symbol(
    vt_symbol=symbol,  # ← 使用 symbol，不是 self.current_vt_symbol
    exchange=exchange,
    start=start_datetime,
    end=end_datetime
)
```

### 修复2: 修改 MultiTimeframeWidget 的参数名

为了避免混淆，可以重命名参数：

```python
def switch_symbol(
    self,
    vt_symbol: str,  # ← 实际上这个参数应该叫 symbol
    exchange: Exchange,
    start: datetime,
    end: datetime
) -> None:
    """
    切换合约
    
    Args:
        vt_symbol: 合约代码（不带交易所后缀，如 "MHImain"）
        exchange: 交易所
        start: 起始时间
        end: 结束时间
    """
    self._vt_symbol = vt_symbol  # 这里存储的是 symbol
    # ...
```

或者更清晰地重命名：

```python
def switch_symbol(
    self,
    symbol: str,  # ← 改名为 symbol
    exchange: Exchange,
    start: datetime,
    end: datetime
) -> None:
    """
    切换合约
    
    Args:
        symbol: 合约代码（不带交易所后缀，如 "MHImain"）
        exchange: 交易所
        start: 起始时间
        end: 结束时间
    """
    self._symbol = symbol
    self._exchange = exchange
    # ...
```

### 如果还是失败

如果还显示 "未找到1分钟K线数据"，检查：

1. **数据库中的数据格式**:
   ```sql
   SELECT symbol, exchange, datetime, interval 
   FROM dbbardata 
   WHERE symbol = 'MHImain' 
   AND exchange = 'HKFE'
   LIMIT 5;
   ```

2. **时间范围是否正确**:
   - 确认 `start` 和 `end` 时间在数据库数据的时间范围内
   - 如果数据只有最近几天，但查询的是上周的数据，也会查不到

3. **交易所枚举值**:
   - 确认 `Exchange.HKFE` 的值与数据库中存储的值一致
   - 可能是 `"HKFE"` 字符串或枚举值

## 快速测试

在 Python 控制台测试数据库查询：

```python
from vnpy.trader.database import get_database
from vnpy.trader.constant import Exchange, Interval
from datetime import datetime, timedelta

database = get_database()

# 测试查询
symbol = "MHImain"
exchange = Exchange.HKFE
end = datetime.now()
start = end - timedelta(days=7)

bars = database.load_bar_data(
    symbol=symbol,
    exchange=exchange,
    interval=Interval.MINUTE,
    start=start,
    end=end
)

print(f"查询结果: {len(bars) if bars else 0} 条数据")
if bars:
    print(f"第一条: {bars[0]}")
    print(f"最后一条: {bars[-1]}")
```

如果这个查询能返回数据，说明数据库没问题，问题在于传参。

## 总结

**核心问题**: symbol vs vt_symbol 的混淆

- `database.load_bar_data()` 需要 **symbol**（不带交易所后缀）
- `ChartWindow.current_vt_symbol` 是 **vt_symbol**（带交易所后缀）
- 需要使用 `extract_vt_symbol()` 分离出 symbol 和 exchange

**修复要点**:
1. ✅ 在调用 `switch_symbol()` 时传入 `symbol` 而不是 `vt_symbol`
2. ✅ 添加详细的日志输出便于调试
3. ✅ 确保时间范围正确
