# Feature Specification: 修复 ChartWindow 实时 Tick 数据刷新

**Feature Branch**: `004-fix-realtime-tick`  
**Created**: 2025-01-27  
**Status**: Draft  
**Input**: User description: "修复 ChartWindow 实时 tick 数据刷新问题，使多周期K线能够实时显示，并使画线交易功能能够正常工作"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 实时查看多周期K线更新 (Priority: P1)

交易员在ChartWindow中打开K线图表，选择任意周期（1分钟、5分钟、1小时、4小时、1日），期望能够实时看到tick数据跳动和正在聚合的K线更新。当市场行情变化时，最后一根K线应该实时更新其价格、成交量等信息，让交易员能够及时观察市场动态。

**Why this priority**: 这是核心功能，没有实时更新，ChartWindow就失去了实时交易工具的价值。用户无法及时做出交易决策。

**Independent Test**: 打开ChartWindow，选择任意周期，订阅行情后，观察最后一根K线是否随着tick数据实时更新。可以通过对比行情窗口的tick数据和图表中的K线变化来验证。

**Acceptance Scenarios**:

1. **Given** ChartWindow已打开并加载了历史数据, **When** 订阅行情后收到tick数据, **Then** 最后一根K线的价格、成交量等信息应该实时更新
2. **Given** 用户切换到1分钟周期, **When** 收到tick数据, **Then** 最后一根1分钟K线应该实时更新
3. **Given** 用户切换到5分钟周期, **When** 收到tick数据, **Then** 最后一根5分钟K线应该实时更新
4. **Given** 用户切换到1小时周期, **When** 收到tick数据, **Then** 最后一根1小时K线应该实时更新
5. **Given** 用户切换到4小时周期, **When** 收到tick数据, **Then** 最后一根4小时K线应该实时更新
6. **Given** 用户切换到1日周期, **When** 收到tick数据, **Then** 最后一根日K线应该实时更新

---

### User Story 2 - 实时画线交易挂单功能 (Priority: P1)

交易员在图表上画一条挂单线（指定价格），期望当市场价格突破该价格时，系统能够自动触发下单。这对于实现自动化交易至关重要。

**Why this priority**: 画线交易是ChartWindow的核心价值功能，挂单功能是画线交易的基础。如果无法实时响应价格变化，整个画线交易功能就不可用。

**Independent Test**: 在图表上画一条挂单线，使用模拟功能或等待真实行情，当价格突破挂单线时，验证是否触发了下单操作。可以通过日志或订单窗口确认。

**Acceptance Scenarios**:

1. **Given** 用户在图表上画了一条买入挂单线（价格X）, **When** 市场价格上涨突破价格X, **Then** 系统应该自动触发买入订单
2. **Given** 用户在图表上画了一条卖出挂单线（价格Y）, **When** 市场价格下跌突破价格Y, **Then** 系统应该自动触发卖出订单
3. **Given** 挂单线已设置, **When** 价格在挂单线附近波动但未突破, **Then** 系统不应该触发订单

---

### User Story 3 - 实时止损止盈功能 (Priority: P1)

交易员在图表上为持仓设置止损线和止盈线，期望当市场价格触及止损或止盈价格时，系统能够自动触发平仓操作，保护利润或限制损失。

**Why this priority**: 止损止盈是风险管理的关键功能，必须在价格触及时立即响应，否则可能导致更大的损失或错失利润。

**Independent Test**: 在图表上为持仓设置止损线和止盈线，使用模拟功能或等待真实行情，当价格触及止损或止盈线时，验证是否触发了平仓操作。

**Acceptance Scenarios**:

1. **Given** 用户持有买单并设置了止损线（价格X）, **When** 市场价格下跌触及价格X, **Then** 系统应该自动触发平仓订单
2. **Given** 用户持有买单并设置了止盈线（价格Y）, **When** 市场价格上涨触及价格Y, **Then** 系统应该自动触发平仓订单
3. **Given** 用户持有卖单并设置了止损线（价格X）, **When** 市场价格上涨触及价格X, **Then** 系统应该自动触发平仓订单
4. **Given** 用户持有卖单并设置了止盈线（价格Y）, **When** 市场价格下跌触及价格Y, **Then** 系统应该自动触发平仓订单

---

### Edge Cases

- 当历史数据还未加载完成时，tick数据应该被忽略，避免在数据不完整时更新图表
- 当切换合约时，应该正确注销旧合约的事件监听，注册新合约的事件监听
- 当窗口关闭时，应该正确注销所有事件监听，避免内存泄漏
- 当EventEngine在不同线程运行时，UI更新应该通过Qt信号槽机制确保在主线程执行
- 当收到非当前显示合约的tick数据时，应该忽略该数据
- 当tick数据频率过高时，系统应该能够处理而不导致UI卡顿
- 当网络中断导致tick数据暂停时，系统应该能够优雅处理，在恢复后继续正常工作

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须能够接收并处理来自EventEngine的EVENT_TICK事件
- **FR-002**: 系统必须在ChartWindow初始化时注册EVENT_TICK事件监听器
- **FR-003**: 系统必须能够过滤tick数据，只处理当前显示合约的数据
- **FR-004**: 系统必须在历史数据加载完成后才开始处理tick更新
- **FR-005**: 系统必须支持1分钟周期的实时K线更新（通过BarGenerator合成）
- **FR-006**: 系统必须支持5分钟周期的实时K线更新
- **FR-007**: 系统必须支持1小时周期的实时K线更新
- **FR-008**: 系统必须支持4小时周期的实时K线更新
- **FR-009**: 系统必须支持1日周期的实时K线更新
- **FR-010**: 系统必须确保UI更新在主线程执行（使用Qt信号槽机制）
- **FR-011**: 系统必须在窗口关闭时注销事件监听器
- **FR-012**: 系统必须在切换合约时正确注销和注册事件监听器
- **FR-013**: 系统必须能够实时检测价格突破挂单线并触发下单
- **FR-014**: 系统必须能够实时检测价格触及止损线并触发平仓
- **FR-015**: 系统必须能够实时检测价格触及止盈线并触发平仓
- **FR-016**: 系统必须保持向后兼容，不破坏现有的历史数据加载和gap补齐功能

### Key Entities

- **TickData**: 实时行情数据，包含价格、成交量、时间等信息
- **BarData**: K线数据，包含开盘价、最高价、最低价、收盘价、成交量等信息
- **ChartWindow**: K线图表窗口，负责显示和管理多周期K线数据
- **EventEngine**: 事件引擎，负责事件的分发和管理
- **BarGenerator**: K线生成器，负责从tick数据合成1分钟K线

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所有周期（1分钟、5分钟、1小时、4小时、1日）的K线都能在收到tick数据后100毫秒内更新显示
- **SC-002**: 价格突破挂单线时，系统能在200毫秒内触发下单操作
- **SC-003**: 价格触及止损或止盈线时，系统能在200毫秒内触发平仓操作
- **SC-004**: 100%的tick数据能够被正确接收和处理（在历史数据加载完成后）
- **SC-005**: 切换合约时，事件监听器能够100%正确注销和重新注册
- **SC-006**: 窗口关闭时，所有事件监听器能够100%正确注销，无内存泄漏
- **SC-007**: 长时间运行（24小时）后，系统仍能正常接收和处理tick数据，无性能退化
- **SC-008**: 画线交易功能（挂单、止损、止盈）的可用性从0%提升到100%
