## 问题背景

之前在不完善的实现（branch `005-multi-timeframe-overlay`）中尝试了多周期K线叠加，但完全不符合要求。现在需要重新分析和设计一个完善的方案。

## 核心问题

**如何将大周期K线（5分钟、1小时、4小时等）全部按照1分钟的时间轴来绘制历史和实时K线？**

## 解决方案概述

### 核心思路

1. **统一时间轴**：以1分钟K线数据作为X轴基准，建立 `datetime -> index` 的映射
2. **时间范围映射**：将大周期K线的起始和结束时间映射到对应的1分钟索引位置
3. **跨索引绘制**：大周期K线在起始索引位置绘制，宽度跨越到结束索引位置

### 关键设计

#### 1. MultiTimeframeBarManager

管理多周期K线数据和时间轴映射：

- **1分钟时间轴基准**：`_base_bars` 存储1分钟K线，`_datetime_index_map` 建立时间到索引的映射
- **大周期K线数据**：`_timeframe_bars` 存储各周期的K线数据
- **时间范围映射**：`_timeframe_range_map` 存储大周期K线到1分钟索引范围的映射

#### 2. 时间范围映射算法

```python
def _calculate_timeframe_range(timeframe, start_datetime):
    # 1. 获取起始时间对应的1分钟索引
    start_ix = get_base_index(start_datetime)
    
    # 2. 计算周期结束时间
    end_datetime = calculate_period_end(timeframe, start_datetime)
    
    # 3. 获取结束时间对应的1分钟索引
    end_ix = find_closest_base_index(end_datetime)
    
    return (start_ix, end_ix)
```

#### 3. 绘制实现

- **1分钟K线**：占据一个索引位置，正常绘制
- **大周期K线**：在起始索引位置绘制，宽度为 `end_ix - start_ix + 1`

### 实时更新策略

1. **1分钟K线更新**：直接添加到基准时间轴，触发大周期K线重新计算
2. **大周期K线更新**：检查当前tick是否属于某个大周期，更新对应K线的 high/low/close
3. **周期完成处理**：当大周期结束时，标记K线为已完成，准备下一个周期

## 关键技术点

### 1. 时间轴映射

**问题**：如何将大周期K线的时间映射到1分钟索引？

**解决方案**：
- 建立1分钟K线的 `datetime -> index` 映射
- 计算大周期K线的起始和结束时间
- 查找对应的1分钟索引位置

### 2. 4小时周期特殊处理

**问题**：4小时K线可能跨越休市时间（如01:15-03:00 + 09:15-11:29）

**解决方案**：
- 实现 `_calculate_4h_period_end()` 方法
- 根据HKFE交易时段规则计算4小时周期边界
- 在时间范围映射时跳过休市时间段

### 3. 实时更新同步

**问题**：如何保证1分钟K线更新时，大周期K线也能同步更新？

**解决方案**：
- 以1分钟K线更新为驱动
- 在 `add_base_bar()` 中检查是否影响大周期K线
- 自动触发大周期K线重新计算

### 4. 性能优化

**问题**：大量K线数据可能导致性能问题

**解决方案**：
- 只绘制可见范围内的K线（已实现）
- 使用缓存减少重复计算
- 批量更新实时K线

// 1. 使用1分钟数据作为X轴基准
let baseData = filteredOneMinData

const timestampToIndex = new Map<number, number>()
baseData.forEach((item, index) => {
    timestampToIndex.set(item.timestamp, index)
})

// 3. 将4小时K线映射到1分钟时间轴
