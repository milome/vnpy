# 挂单触发错误原因分析

**日期**: 2025-12-03  
**问题**: 为什么之前有的委托挂单成交了，有的却报一个dict的错误？

---

## 问题现象

- ✅ **部分挂单成功**：正常触发下单，订单成功提交并成交
- ❌ **部分挂单失败**：触发下单时出现 `unhashable type: 'dict'` 错误

---

## 根本原因分析

### 1. 富途API返回数据的不一致性

在 `FutuGateway.send_order` 方法中（`vnpy_futu/vnpy_futu/futu_gateway.py:1652-1687`）：

```python
code, data = self.trade_ctx.place_order(...)

if code:
    self.write_log(f"委托失败：{data}")
    return ""

for ix, row in data.iterrows():
    orderid: str = self._normalize_orderid(str(row["order_id"])) or str(row["order_id"])

# 创建订单对象
order: OrderData = req.create_order_data(orderid, self.gateway_name)
self.on_order(order)

return order.vt_orderid
```

**问题点**：

1. **正常情况下**：
   - `place_order` 返回 `(0, DataFrame)`，其中 DataFrame 包含订单信息
   - `data.iterrows()` 正常执行，`row["order_id"]` 是字符串
   - `order.vt_orderid` 是字符串，如 `"FUTU.6458744"`

2. **异常情况下**（导致dict错误）：
   - `place_order` 可能返回 `(0, dict)` 或 DataFrame 中的 `order_id` 字段是字典
   - 如果 `row["order_id"]` 是字典，`str(row["order_id"])` 会返回字典的字符串表示（如 `"{'key': 'value'}"`）
   - 或者在某些边界情况下，`data` 本身可能是字典而不是 DataFrame

### 2. 类型转换问题

在 `widget_trigger.py` 中（修复前）：

```python
controller._line_order_map[line_id] = vt_orderid
controller._order_line_map[vt_orderid] = line_id  # ❌ 如果 vt_orderid 是 dict，这里会报错
```

**问题**：
- 如果 `vt_orderid` 不是字符串而是字典，尝试将其作为字典键使用时，会抛出 `unhashable type: 'dict'` 错误
- 字典是不可哈希的类型，不能作为字典的键

### 3. 为什么是间歇性的？

**可能的原因**：

1. **富途API的响应不一致**：
   - 正常情况：返回 DataFrame，`order_id` 是字符串
   - 异常情况：返回字典或 DataFrame 中的 `order_id` 是字典
   - 可能发生在网络延迟、API限流、或特定市场条件下

2. **数据处理的边界情况**：
   - 如果 `data` 是空的 DataFrame，循环不执行，`orderid` 未定义
   - 如果 `row["order_id"]` 是字典，`str()` 转换后仍然是字典的字符串表示
   - `_normalize_orderid` 可能返回非字符串类型

3. **异常处理不完整**：
   - 代码假设 `place_order` 总是返回 DataFrame
   - 没有检查 `data` 的类型
   - 没有验证 `order_id` 的类型

---

## 修复方案

### 1. 在 `FutuGateway.send_order` 中添加类型检查

```python
code, data = self.trade_ctx.place_order(...)

if code:
    self.write_log(f"委托失败：{data}")
    return ""

# ✅ 添加类型检查
if not isinstance(data, pd.DataFrame):
    self.write_log(f"警告: place_order 返回了非DataFrame类型: {type(data)}, 值: {data}")
    return ""

if data.empty:
    self.write_log("警告: place_order 返回了空的DataFrame")
    return ""

# 安全地获取 order_id
orderid = None
for ix, row in data.iterrows():
    order_id_value = row.get("order_id")
    if order_id_value is not None:
        # ✅ 确保 order_id 是字符串
        if isinstance(order_id_value, dict):
            self.write_log(f"警告: order_id 是字典类型: {order_id_value}")
            # 尝试从字典中提取订单ID
            orderid = str(order_id_value.get("order_id", order_id_value))
        else:
            orderid = str(order_id_value)
        break

if not orderid:
    self.write_log("错误: 无法从返回数据中获取订单ID")
    return ""
```

### 2. 在 `widget_trigger.py` 中添加类型检查（已修复）

```python
# ✅ 确保 vt_orderid 是字符串类型
if not isinstance(vt_orderid, str):
    if main_engine:
        main_engine.write_log(
            f"[ChartWidget] 警告: send_order 返回了非字符串类型: {type(vt_orderid)}, 值: {vt_orderid}",
            "ChartWidget"
        )
    # 尝试转换为字符串
    vt_orderid = str(vt_orderid) if vt_orderid else None

if vt_orderid:
    # 使用 controller 的方法关联订单和挂单线（更安全）
    if hasattr(controller, 'link_line_to_order'):
        controller.link_line_to_order(line_id, vt_orderid)
    else:
        # 向后兼容：如果方法不存在，直接操作字典
        controller._line_order_map[line_id] = vt_orderid
        controller._order_line_map[vt_orderid] = line_id
```

## 为什么有些成功、有些失败？

### 成功的场景

1. **正常情况**：
   - `place_order` 返回 DataFrame
   - `row["order_id"]` 是字符串
   - `order.vt_orderid` 是字符串
   - 关联操作正常执行

### 失败的场景

1. **API返回异常**：
   - `place_order` 返回字典或 DataFrame 中的 `order_id` 是字典
   - `order.vt_orderid` 变成了字典
   - 尝试将字典作为字典键使用时失败

2. **数据格式不一致**：
   - 富途API在不同情况下可能返回不同格式的数据
   - 某些错误情况下返回字典格式的错误信息
   - 代码没有处理这些边界情况

---

## 预防措施

### 1. 添加类型检查

- 在 `send_order` 中检查返回数据的类型
- 在 `widget_trigger.py` 中检查 `vt_orderid` 的类型
- 确保所有字典键都是可哈希的类型（字符串、数字等）

### 2. 添加异常处理

- 捕获类型转换异常
- 记录详细的错误日志
- 提供降级处理方案

### 3. 验证数据格式

- 验证 `place_order` 返回的数据格式
- 验证 `order_id` 的类型和格式
- 验证 `vt_orderid` 的格式

---

## 总结

**为什么有些成功、有些失败？**

1. **富途API的响应不一致**：在某些情况下返回的数据格式不符合预期
2. **缺少类型检查**：代码没有验证返回数据的类型
3. **异常处理不完整**：没有处理边界情况和异常数据格式

**修复后的改进**：

1. ✅ 添加了类型检查，确保 `vt_orderid` 是字符串
2. ✅ 添加了异常处理，记录详细的错误日志
3. ✅ 提供了降级处理方案，避免程序崩溃

这样即使富途API返回异常数据，代码也能正确处理，不会导致程序崩溃。
