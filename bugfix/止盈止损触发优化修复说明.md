# 止盈止损触发优化修复说明

**日期**: 2025-12-03  
**问题**: 订单成交后、持仓更新为0之前，止盈/止损线继续触发导致"暂无持仓"错误  
**状态**: ✅ 已修复

---

## 问题描述

### 问题表现

从日志可以看到以下问题：

1. **02:41:00.867** - 止盈线触发，下单（订单6458744）
2. **02:41:04.049** - 防抖期过了（3秒），又触发止盈，但委托失败："暂无持仓"
3. **02:41:08.549** - 再次触发止盈，仍然失败："暂无持仓"
4. **02:41:09.208** - 订单6458746完全成交，持仓更新为0，止盈线被删除

### 根本原因

1. **持仓检查不完整**：
   - 在检查持仓时，只检查了 `position.volume <= 0`
   - 但没有提前检查 `available_volume`（可用持仓 = volume - frozen）
   - 当持仓被冻结（正在平仓中）时，`available_volume <= 0`，但 `volume > 0`，导致继续触发

2. **订单状态更新延迟**：
   - 订单成交后，持仓更新为0需要时间
   - 在这段时间内，止盈/止损线仍然存在，仍然在触发检查
   - 虽然检查了未成交订单，但订单可能已经成交，只是持仓还没更新

3. **可用持仓检查位置不当**：
   - `available_volume` 的检查在计算 `close_volume` 之后
   - 应该在检查持仓后立即检查 `available_volume`，避免不必要的计算

---

## 修复方案

### 修复内容

在 `vnpy/chart/widget_trigger.py` 中，对 `trigger_stop_loss_close` 和 `trigger_take_profit_close` 两个方法进行了修复：

1. **提前检查可用持仓**：
   - 在检查持仓后，立即检查 `available_volume`
   - 如果 `available_volume <= 0`，说明持仓已被冻结（正在平仓中），应该跳过
   - 添加了明确的日志说明："可用持仓为0，可能正在平仓中"

2. **优化检查顺序**：
   - 先检查 `position.volume <= 0`（无持仓）
   - 再检查 `available_volume <= 0`（持仓被冻结）
   - 最后计算 `close_volume`（可平仓手数）

### 修复代码

**止损线修复**（`trigger_stop_loss_close`）：
```python
# ✅ 提前检查可用持仓：如果持仓被冻结（正在平仓中），应该跳过
available_volume = position.volume - position.frozen
if available_volume <= 0:
    # 可用持仓为0，说明持仓已被冻结（正在平仓中），应该跳过
    if main_engine:
        main_engine.write_log(
            f"[ChartWidget] 触发止损跳过: 止损线 {line_id} 可用持仓为0（持仓={position.volume}, 冻结={position.frozen}），可能正在平仓中",
            "ChartWidget"
        )
    return False
```

**止盈线修复**（`trigger_take_profit_close`）：
```python
# ✅ 提前检查可用持仓：如果持仓被冻结（正在平仓中），应该跳过
available_volume = position.volume - position.frozen
if available_volume <= 0:
    # 可用持仓为0，说明持仓已被冻结（正在平仓中），应该跳过
    if main_engine:
        main_engine.write_log(
            f"[ChartWidget] 触发止盈跳过: 止盈线 {line_id} 可用持仓为0（持仓={position.volume}, 冻结={position.frozen}），可能正在平仓中",
            "ChartWidget"
        )
    return False
```

## 修复效果

### 预期效果

1. **避免重复触发**：
   - 当持仓被冻结（正在平仓中）时，立即跳过触发检查
   - 避免在订单成交后、持仓更新为0之前继续触发

2. **减少错误日志**：
   - 不再出现"暂无持仓"的错误日志
   - 提前检查可用持仓，避免发送无效订单

3. **提高系统稳定性**：
   - 减少不必要的订单请求
   - 避免因重复触发导致的系统错误

### 验证要点

修复后，应该验证以下场景：

1. **正常触发场景**：
   - 止盈/止损线触发时，持仓存在且可用持仓 > 0，应该正常下单

2. **持仓冻结场景**：
   - 止盈/止损线触发时，持仓存在但可用持仓 = 0（被冻结），应该跳过并记录日志

3. **持仓为0场景**：
   - 止盈/止损线触发时，持仓为0，应该跳过并记录日志

4. **订单成交后场景**：
   - 订单成交后，持仓被冻结或更新为0，应该不再触发

## 注意事项

1. **持仓冻结机制**：
   - 当订单提交后，持仓会被冻结（`frozen > 0`）
   - 订单成交后，持仓会更新为0，但这个过程可能有延迟
   - 通过检查 `available_volume`，可以提前发现持仓被冻结的情况

2. **防抖机制仍然有效**：
   - 3秒防抖机制仍然有效，可以防止短时间内重复触发
   - 但防抖期过后，如果持仓被冻结，仍然会跳过触发

3. **未成交订单检查**：
   - 检查未成交订单的逻辑仍然有效
   - 但通过提前检查可用持仓，可以更早地发现持仓被冻结的情况
